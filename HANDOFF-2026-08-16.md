## 2. Why this branch exists (one paragraph)

Google Play removed the app: "uploading users' phone number information
without a prominent disclosure" (User Data policy). Focusing the phone field
read the SIM's number via a permission-free Play Services API and auto-sent it
to our server and MSG91 with zero user action. That is fixed with a dedicated
disclosure + consent gate, and three audits (two code-level, one against the
live Play policy pages) closed every other exposure of the same shape. Along
the way, most of the app's money-honesty bugs got fixed because they were
Deceptive Behavior exposure too.

## 3. Env vars the app needs TO WORK FOR REAL

All `EXPO_PUBLIC_*` values are **baked into the JS bundle at build time**.
They must be set in the EAS build environment (dashboard env vars, and add
`"environment": "production"` to the production profile) — a `.env` file does
NOT reach EAS builds. Locally, `.env` works but Metro inlines the values into
its transform cache: after changing `.env`, restart with `npx expo start -c`.

### App (consumer)

| Var | Required? | Production value / rule |
|---|---|---|
| `EXPO_PUBLIC_API_URL` | **YES — the app is dead without it** | The deployed backend, **https**, and it MUST include the mount path: `https://<host>/api/v1/consumer`. The app appends routes directly (`${API_URL}/auth/otp/request`), so a bare host 404s everything. Empty → release build refuses sign-in on purpose (no silent demo mode; the old `123456` fallback is `__DEV__`-only now). |
| `EXPO_PUBLIC_CONSUMER_APP_KEY` | **YES** | Must equal the backend's `CONSUMER_APP_KEY`. The backend fails CLOSED: mismatch or unset → every consumer read 403s. |
| `EXPO_PUBLIC_RAZORPAY_KEY_ID` | YES for payments | A **new** live key. The old `rzp_live_T0Lw…` was committed to git twice and must be treated as burned — rotate it at Razorpay before launch. Empty → checkout refuses to open (there is deliberately no fallback key any more). |
| `EXPO_PUBLIC_WALLET_TEST_TOPUP` | **must be `false`** | `true` arms the mock top-up, shows the dev-OTP hint, and (with `__DEV__`) the demo order buttons. The EAS production profile pins it false — leave that alone. |
| `EXPO_PUBLIC_CATALOG_BACKEND_AUTHORITATIVE` | recommended `true` | Products render server-side from `GET /catalog`. Only set `true` when the backend runs `CONSUMER_CATALOG_SEED_SERVE=true` (or has a real catalog), else the bundled `constants/products.ts` is the source. |
| `EXPO_PUBLIC_GOOGLE_PLACES_KEY` | optional | Address autocomplete. Absent → typed search is unavailable; the city-picker + map-pin path still works. Note: what the user types goes to Google — this is disclosed in-app and must be declared "shared" on the Data Safety form. |
| `EXPO_PUBLIC_CARE_PHONE` | optional override | Defaults to the operator-confirmed `+91 96672 60050` (lib/support.ts). |
| `EXPO_PUBLIC_CARE_WHATSAPP` | optional | Full international digits (`91…`). Absent → the WhatsApp row hides. Never put a stand-in number here. |
| `EXPO_PUBLIC_MSG91_*` | **DO NOT SET for store builds** | `EXPO_PUBLIC_*` ships inside the APK — a client-side MSG91 authkey is extractable by anyone. OTP must go through the backend. The old authkey was committed to git (`supabase/functions.env`, still in history on four branches): **rotate it at MSG91** regardless. |

## 4. Run it locally in ~10 minutes

```bash
# Backend (Go 1.24+; Mongo already running via brew services)
cd parag-saathi-be
go run ./cmd/seed          # idempotent; creates orgs, parties, demo consumer 9000000051
PORT=8090 go run ./cmd/server

#   EXPO_PUBLIC_API_URL=http://localhost:8090/api/v1/consumer
#   EXPO_PUBLIC_CONSUMER_APP_KEY=<same as backend CONSUMER_APP_KEY>
```

verify → JWT session against the real backend.

## 5. What changed, by area (read the commit messages — they carry the why)

- **Prominent disclosure + consent gate** (`components/DataDisclosure.tsx`,
  `lib/dataConsent.ts`, `app/(auth)/otp.tsx`). Seven data flows disclosed. The
  gate is enforced on the transmit path (`sendCodeFor`) as well as the UI.
  Post-acceptance, focusing the field launches the SIM chooser again (the
  zero-typing feel) — but picking only FILLS the field. **The auto-send stays
  dead. Do not reintroduce it, ever.**
- **Instant lane = wallet OR pay-on-delivery, the member picks**
  (`components/InstantPlaceSheet.tsx`, `app/cart.tsx`, `app/product/[id].tsx`,
  `app/order/[id].tsx`, `lib/api.ts`). Wallet is offered only while the balance
  covers the bill and debits at placement (cancel refunds instantly); COD
  charges nothing at placement, settled by UPI en route or cash at the door.
  THE AUTO-PLACE SPLIT IS LOAD-BEARING: the 3-second cancel-grace auto-place
  runs for COD ONLY, because no money moves; a wallet placement always needs an
  explicit "Place and pay" tap — a timer that debits on its own is the dark
  pattern the consent rules exist to stop. Do not merge the two paths.
  Pay-while-we-deliver (Razorpay) is local-mode only until the backend has a
  verified payment endpoint (`markOrderPaid` documents the seam).
- **Money honesty**: cancel refunds (`refundToWallet` finally has call sites);
  trial flipped so the FIRST two days are free and the sweep actually honours
  them (`lib/trial.ts`, `lib/subscriptionSweep.ts`); Plus perks are real
  (member price on milk + priority slots, applied in `placeOrder`, the single
  money source of truth) or no longer sold; GST table on the post-Sep-2025
  slabs (needs CA sign-off).
- **Legal identity**: real GSTIN/CIN/registered office from the published
  policy docs; `/privacy` `/terms` `/delete-account` URLs verified live
  (constants in `lib/support.ts`). The in-app Privacy Policy and Terms are the
  published v1.0 texts. No placeholder language anywhere user-visible.
- **Permissions** (verified on the built APK, not source): location, camera,
  internet, vibrate, legacy storage ≤32 only. `RECORD_AUDIO`,
  `SYSTEM_ALERT_WINDOW`, `USE_BIOMETRIC`, `USE_FINGERPRINT` all blocked in
  `app.json`.

## 6. Landmines — do not step on these

1. **Never gate demo/dev behaviour on "backend not configured".** That exact
   pattern shipped the demo app to production. Dev-only = `__DEV__`.
2. **Never put a fallback payment key or a client-side SMS key in code.**
3. **Play Console privacy URL is `/privacy`** — `/privacy-policy` 404s and an
   automatic rejection.
4. Resubmission requires **deactivating every bundle ≤ versionCode 28 on all
   four tracks** (production, open, closed, internal), or it fails silently.
5. The published Terms/Privacy PDFs print `+91 99996 80081`; the operator says
   the real line is `9667260050`. The public documents need reissuing.
6. `assets/banners/home-banner-2.png` still claims a "7-day subscription" and
   "free milk packets" — untrue; artwork replacement pending (owner).
7. Expo SDK 56 has a known Hermes memory regression (fixed in SDK 57 / RN
   0.86.2). Upgrade deliberately, not mid-release.
8. Cleartext HTTP is blocked in release builds on both platforms — a physical
   device cannot talk to `http://<LAN-IP>`. Real-device E2E needs the https
   backend.
